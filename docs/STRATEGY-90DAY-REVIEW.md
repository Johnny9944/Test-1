## 2. 这些 flow 能不能组成一人公司、能不能获利

**结论:90 天内不成立(feasible=False);条件补齐后可小规模做,天花板很低。**

**必须先满足的条件**:
- 【最便宜、最该马上做的一条】确认 R22.8 发消息走的是不是官方通道。问 CC-A 一句话:那个发消息的 HTTP 节点,域名是什么?三种结果三种走法——graph.facebook.com 是官方直连,可以往下想;是某个服务商的域名(respond.io / 360dialog / Wati 一类)也是官方的,可以往下想;是本机跑的那种非官方库,那么「帮别人的号装机器人」这条最值钱的产品线当场划掉,永远不卖。这一句话决定这门生意一半的收入。
- 他自己的 Phase 0a ①–④ 与 Phase 0b ⑤–⑨ 九项验收全部通过。理由不是完美主义:导入实测没做完,就没人知道在 n8n 里改客户的线上流会不会变成「新旧两条一起跑、帖子发两遍」。给自己发两遍是尴尬,给客户发两遍是事故加退款。而这套「改完能证明确实上线了」的纪律(回归三个数、三段哈希、回滚点、上线后观察 30 分钟),恰恰是本地那些代运营公司给不出来的东西——它才是他真正能卖的差异化。
- lead_attribution 验收通过,并且有连续 2 周他自己生意的真实数据。「我能帮你看出哪条广告真的带来成交」是唯一能撑住溢价的卖点,现在是零证据;没有它,他卖的跟别人一样只是一张报表。
- 公司书面回复到手,而且在同一封信里顺带问清一句:「我能不能向其他分销商提供付费的技术服务?」不问清就去同行群里卖东西,可能被当成跨线招揽,一次投诉就把许可信谈崩,连带 Phase 1 和整个广告引擎一起归零。
- SSM 独资注册(约 RM60)+ 一页自写服务条款 + 能开发票;顺便查清电子发票对他这个营业额档的强制起始日期(现在未知)。诊所、补习中心、美容院这类正规客户没有发票根本付不了钱——这是最便宜也最容易被忘掉的一道门。
- 三条永久铁规,写下来贴在桌上:一、绝不替客户托管 n8n,客户自持服务器、自持账单、自持全部账号所有权,他只收配置与运维人工费;二、绝不把客户的 Page 或广告账户并进他自己那个装着 4 个 Page 的 Business Portfolio——一个客户违规会连坐他自己四条产品线的自然流量,这是唯一一个能一次性毁掉整间公司的决定;三、绝不索取客户的登录密码。
- 一条自动刹车,直接照抄他自己广告规则里的 R10:任何一周只要出现「我自己的线索 24 小时没回超过 3 条」,立刻停止接新客户,下一个往后推两周。服务业务最常见的死法不是没客户,是客户把他回 WhatsApp 的时间吃光,自己的生意先垮。
- 同时服务的客户数硬上限 3 个,同一时间只 onboarding 1 个。这不是保守,是算出来的:他每月净可交付 12–18 小时,第一个客户光 onboarding 就要 20–30 小时。

**推荐第一个卖的包**:「每日生意数字 + 月底对账」只读包 —— 不碰客户的号、不碰客户的钱、不碰客户的文案
- 价格:建置 RM1,200 + 月费 RM300;头两个客户走案例价:建置 RM600 + 月费 RM200,换一份书面见证和「可以引用你的数字(脱敏后)」的授权
- 为什么:选它不是因为最赚钱,是因为它是唯一一个「已经在他自己生意上跑起来、而且万一出事也伤不到客户」的东西。零件全是现成的:Apps Script 的 Sheets 桥四个动作已经由老板亲手部署并测通,SE-09 每天把广告花销写回 Ratio 表正在用 Meta 只读 token 干跑,R22.11 自动数进线一天内核对完——到下周他手上就有一周自己生意的真实数据可以直接截图给客户看。它绕开了所有还没答案的问题:不用碰客户的 WhatsApp 号(所以那个未确认的通道问题不影响它),不用写一个字的文案(所以 Act 290 和公司许可都跟它无关),不用动客户的广告预算一分钱(所以没有代运营那种责任错配)。客户只给两样东西:一张他自己的 Google Sheet 的编辑权,和一个只勾了「看广告数据」的只读 token。交付内容就四句话:每天早上一条消息告诉他昨天花了多少、进了几条、累计成了几单、比例是多少;每周一张按线分的表;每月 1 号拿广告后台账单、Sheet、成交表三方对一次,差超过 RM5 就报警;同类告警一小时内只发一次不刷屏。稳态工时 2.5–4 小时/月,是所有候选里工时最低、爆炸半径最小的一个。刻意不卖的是「成交归因」——那部分等他自己的 lead_attribution 验收通过、跑满两周再当加价项加进去,现在写进合同就是卖一个没验过的功能。

**现在不能卖的**:
- WhatsApp 机器人搭建与托管。先回答通道是不是官方的;就算是官方的,也要等每客户独立实例、合同四件套、导入实测三样都做完。这是收入潜力最大的包,也是最容易把客户主力号搞没的一个——客户号被封等于断他当天的现金流,索赔可以远超服务费。
- 广告代投与代运营,连「只出建议、不碰你预算」的版本也不行。R1–R10 那些阈值在方案里白纸黑字写着「全为占位」,他自己一分钱广告都还没花过。最早能重新讨论是自己跑完 A-2(连续 7 天全自动、对账 ±RM5、滚动 ≥3:1)并累积 60 天真实数据之后,现实上是 2027 年第二季度,不是视角 1 说的 2026-12。
- IG / Threads / TikTok / YouTube 自动发帖。他自己在这些平台上一帖都没自动发过,4 个 IG 连养号都没开始。只卖已经在生产环境跑起来的东西——FB 自动发帖(v3.9.19,4 个 Page 在跑)是真的,其他都还是文档。
- 把「能追到成交」写进任何合同或报价单。lead_attribution 未验收,这等于卖一个没验过的功能。等自己跑通两周再加,加的时候还能顺手涨价。
- 独立收费的合规咨询包。先花 RM800–2,500 问一次大马律师(方案自己把「完全不提功效是否真能免 KKLIU」列为最贵的未知);而且客户真正的阻塞是公司批不批,一张词表解决不了。现在它只能当自用工具和赠品。
- 客户对话语料诊断。现有解析器是 Telegram 格式,WhatsApp 要重写;更重要的是这涉及客户的客户的敏感个人资料,PDPA 2024 修正后他作为数据处理者直接担责。
- 任何 24/7 或 uptime 数字承诺。他一个人、晚上处理、非技术;客户的紧急情况(号不回消息、广告一夜烧超)正好都发生在他睡觉的时候。合同只能写「每天 10:00–22:00 尽力响应」。
- 任何需要他持有客户密码、或把客户的 Page / 广告账户并进他自己 Business Portfolio 的做法。前面几条是暂缓,这一条是永远。
- 向同公司分销商和自己的下线卖任何付费服务——直到公司书面确认这不算跨线招揽。

**保守收入估算(月)**:
- 第 3 个月:RM0–600/月(约 2026-12)。最可能的答案就是 0。到 12 月,他自己的 Phase 0a/0b 才刚跑完、Phase 1 刚开工、广告 A-1 可能才起步,手上既没有可展示的归因数据、也没有客户案例,SSM 和发票能力大概率也是 11 月才补上。乐观一点是签下 1 个案例价客户(建置 RM600 一次性 + 月费 RM200),摊到月度约 RM400。这不是悲观估计,是「前置条件一个都没补齐」的默认结果。
- 第 6 个月:RM600–1,800/月(约 2027-03)。构成:2 个只读对账客户(1 个案例价 RM200 + 1 个正价 RM300)+ 每季度 1 个建置 RM1,200 摊到三个月约 RM400,毛收入约 RM900;扣掉每客户 RM100–200 的基础设施,净约 RM400–1,300。上限那头是签到 3 个客户并且有一个升级加了归因模块。这一档对应他每月投入 12–18 小时,有效时薪约 RM40–90——低于他自己多成一单的毛利,这个事实必须摆在桌面上。
- 第 12 个月:RM1,500–4,000/月(约 2027-09),而且必须同时成立两件事:(a) WhatsApp 通道确认是官方的,能加卖 1–2 个机器人托管席位(RM300–500/月一个);(b) 托管工时实测确实 ≤3 小时/客户/月。任何一条不成立,就停在 RM1,200–2,500。不招人的物理上限是 3–4 个活跃客户;要过 RM5,000 必须招一个兼职(RM1,500–2,500/月)分担支持和催素材,净利率会从约 70% 掉到 50% 左右。

## 4. YouTube 等平台什么时候开始

90 天内不做,也不要为它单独立项。最早 2026-12 下旬到 2027-01,而且只做最轻的一种形态。形态说清楚:复用现在内容管线已经会产出的那段 60–90 秒口播脚本(和 TikTok 同一条,不用再调一次模型、不用新建工作流),在半自动内容包里多加一个字段「YouTube 标题 + 描述(带跳转链接)」,老板拍完在手机上复制粘贴自己发,发完把链接回贴,系统记一笔。归因靠跳转链接和来源码,不接 YouTube 的任何接口。同时记得把 YT 加进来源码的正则,不然 YouTube 来的人会全部落进「无码进线」,把日报里那个本来用来诊断文案的指标弄脏。三个放行条件:半自动内容包已经上线并连续两周回填率 ≥80%;三语禁词表已经初始化(YouTube 对保健品的医疗宣称审得跟 Meta 一样严,词闸没上线就等于多开一个没人看门的出口);老板的实拍产能稳定到每周能出 2–3 条竖版短片。为什么不是 11-09:那个日期建在 Phase 2 从 10-07 起算的基线上,而 Phase 1 现在已经要推到 10 月中下旬,Phase 2 自然顺延到 11 月底以后。为什么不值得早做,只讲两个数:接口那条路现在是死的(未审计的项目上传会被锁成私密,跑成功了也没人看得到,要解锁得过合规审计,几周到几个月不定);而播放量那条路对这门生意可以当零算——Shorts 的分成大约是一百万次播放换 RM45–330,而他一单的毛利就是 RM600–1,200,也就是说一百万次播放的全部分成还换不来一单(这两个行业数字都是二手口径,正式做之前要在后台再确认一次)。反过来,一条 Shorts 只要带来一两个进线,价值就把任何量级的分成甩开了。所以 YouTube 对他唯一的意义是「一个免费的短视频分发口,把人导进 WhatsApp」;追订阅、追播放、追开通分成计划都是走错方向。要现在就手发一条玩玩完全可以,那属于老板自己拍着玩,零系统成本、不占任何排期,但别指望它能算出账。

形态:仅脚本 + 老板手发（半自动），三点具体做法:(1) 复用现成产物，不新建管线——SPEC §4 的派生 JSON 已经强制包含 tiktok_script(60–90 秒口播脚本)与 3 条 caption，YouTube Shorts 的口播脚本与 TikTok 同一条即可，不需要第二次 OpenAI 调用、不需要新工作流;(2) 只在 SE-09 内容包里多加一个字段「YouTube Shorts 标题 + 描述(含 go.daelifeai.com/<code> 链接)」，老板在手机上拍完直接复制粘贴发布，回贴视频链接 → 写 post_log(is_manual=true)，归因靠 go 跳转记点击 + 来源码，不靠 YouTube 的任何 API;(3) 来源码用独立前缀(如 #YT_DNG_1109A)，并把 YT 加进 SE-07 的来源码正则——否则 YouTube 来的线索会全部落进 match_method=none，日报的「无码进线 %」会被污染，看起来像文案写坏了。明确不做的:不接 YouTube Data API、不做合规审计、不做 OAuth 同意屏发到 Production、不做自动上传。;最早:2026-11-09(周一)。推算依据:SPEC §7 的 Phase 2 是「约 2026-10-07 起，1 个月」，SE-09 SemiAuto Pack（TikTok/小红书半自动内容包）在 Phase 2 交付；按当前落后 1–2 周顺延，SE-09 内容包实际上线约 10 月下旬，再要求它稳定运行两周、半自动回填率 ≥80%（Phase 2 的验收口径），最早能顺带加 YouTube Shorts 字段就落在 11 月初。放行条件三条:① SE-09 内容包已上线且连续两周回填率 ≥80%;② gate_rules 三语词表已初始化（Phase 1 交付项）——YouTube 对保健品医疗宣称的审查与 Meta 同级，Gate 没上线就多一个未过闸的出口;③ 老板的实拍产能已稳定到每周能出 2–3 条竖版短片（Shorts 每周少于 2–3 条拿不到算法反馈，做了等于没做）。这三条任一条不满足就继续往后推，不要为了凑平台数量硬上。。

4. 【CC-B 做,老板只需配合三次、总共约 30 分钟】本周把 Phase 0a 那六个不需要等任何人的技术项补完,顺序固定:先任务 0(只读拉 R22.8 的 JSON,判断它认不认新的来源码格式)→ 写部署核对工具链和 token 扫描 → 在导入任何真实工作流之前,先用一个空壳工作流实测两条导入路径,把结论写进 DEPLOY-SOP(这一步没做完不许导入真东西,否则新旧两条流一起跑,帖子会发两遍)→ SE-00 Router 最小版 + SE-07 进线归因 → v3.10 帖尾唯一来源码。老板要配合的三次:周二晚在空壳工作流上点两三次发布(10 分钟)、周三用测试号点一条预填链接发出去看归因有没有记上(5 分钟)、周四看一眼 v3.10 的改动点个头(15 分钟)。这六项不是「顺便做的技术活」——它们产出的部署纪律,将来才是你向客户收托管费时唯一拿得出手的凭证。
5. 【老板亲自做的决定,不是执行 · 现在就定下来,省掉后面 12 周的纠结】这 90 天不开服务公司。理由三句话:第一,现在唯一经得起演示的只有黑名单同步和 FB 自动发帖,最能卖的那个包卡在一个五分钟就能问清、却还没人问的问题上;第二,你每月净可交付 12–18 小时,光第一个客户的 onboarding 就要 20–30 小时,接一个客户就等于停掉自己的 Phase 1 和广告引擎一个月;第三,服务业务 base 档整整一个月的净收入,大约只等于自己多成一两单。把这 90 天全部押在自己的生意上,跑出 Phase 0a/0b 验收、Phase 1 上线、广告 A-1 拿到真实获客成本——这套数据本身就是将来卖服务时最值钱的案例。如果实在想试水,只做一件事、只做一次:找 1 个非保健品、你本人认识的本地商家,用 RM600 的案例价做那个「每日生意数字 + 月底对账」只读包,目的不是赚这 RM600,是量出真实工时到底是 3 小时还是 8 小时。这个数字决定 2027 年要不要认真做这门生意。

## 6. 批评家砍掉/降级的说法

- **「包 A 客户对话诊断现在就能卖」「语料引擎改成 WhatsApp 统计即可,零新增开发」「只需 8–12 小时把词典抽成配置」(视角 1、视角 2)**
  - 为什么不成立:现有 tools/tg-parse.mjs 解析的是 Telegram 的 JSON 导出格式;客户手上的是 WhatsApp 对话,导出来是纯文本 .txt、一行一条、没有结构化字段,解析、去重、增量导入、脱敏全部要重写,不是换个词典的事。而且他自己跑通的语料是同行群(38 聊天 / 4.3K 消息),不是客户售前对话,四线词典 313–388 词是按 DNG/GSD/FLX/RUM 硬绑的。更麻烦的是客户的客户从没同意把对话交给第三方分析,保健类内容里的健康状况在 PDPA 2024 修正后属敏感个人资料,数据处理者现在直接担责。
  - 修正:不是「零开发」,是 25–40 小时(WhatsApp 解析器 + 行业词典配置化 + 脱敏 + 数据处理协议 + 客户自行导出指引)。90 天内不卖。要试水就先拿自己已有的 Telegram 语料做一份脱敏样板报告当作品集,入口价从 RM300–500 的「只看不存、当场看完就删」体检起步,不是 RM1,800。
- **「只读看一眼 R22.8 的 HTTP 节点域名,不是 graph.facebook.com 就一票否决包 C」(视角 1)**
  - 为什么不成立:结果不是两种,是三种。除了官方直连和非官方库(whatsapp-web.js / Baileys 一类),还有很常见的第三种:经正规服务商(respond.io、360dialog、Wati 这类)走官方通道,域名不是 graph.facebook.com 但完全合法。按「域名不对就枪毙」会误杀一个本来能卖的产品线。
  - 修正:问题改成三选一:(a) graph.facebook.com/v*/{id}/messages = 官方直连,合法,ctwa_clid 拿得到;(b) 某个服务商的域名 = 官方但经第三方,合法,ctwa_clid 要看对方给不给;(c) 本机跑的 puppeteer/Baileys/whatsapp-web.js = 非官方,自用自担风险,绝不能卖给别人。只有 (c) 是一票否决。
- **「MRR 天花板 RM8,000–12,000」「第 9–12 个月 RM12,000–18,000/月」(视角 1)**
  - 为什么不成立:同一份评估自己写了可交付工时 28–42 小时/月;高档要 8–12 个托管席位、每席 ≤3 小时 = 24–36 小时,已经吃满全部工时,一分钟不留给销售、onboarding、事故和他自己的生意。还要同时满足「通道是官方的」「托管工时真能压到 3 小时」「招到兼职」三件事,连乘概率很低。更根本的是:真正干活的是 Claude 会话,而用量是账号级 5 小时滚动窗口(2026-09-09 晚三会话并行 3 小时就撞限),客户越多,越会在出事那天恰好没额度。
  - 修正:不招人的现实天花板是 3–4 个活跃客户、MRR RM1,200–2,500;招 1 个兼职(RM1,500–2,500/月)后到 RM3,000–5,000,净利率从约 70% 掉到 50% 左右。RM12,000–18,000 不应该出现在任何一份计划里。
- **「包 B 只读对账补个 client_id 就能卖,卖点是能追到成交,COGS RM40–120/月、毛利 73–91%」(视角 1)**
  - 为什么不成立:「能追到成交」恰恰是唯一没验过的部分:lead_attribution 未验收、v3.10 唯一来源码未做、任务 0 结论没出、go 跳转要等 Phase 1。今天能证明的只有「花了多少」和「进了几条」,「成了几单」还是老板手填。另外同一份评估在风险段又把托管类 COGS 写成 RM140–330/月,两个数字自己打架;按每客户独立实例的正确做法,RM40–120 不成立。
  - 修正:卖点降级成「花了多少 + 进了几条 + 月底三方对账不差钱」,成交归因等自己验收通过再作为加价项写进合同;COGS 一律按 RM100–200/客户/月 计(客户自持实例并自付账单时降到 RM20–50);价格相应降到建置 RM1,200 + 月费 RM300。
- **「包 F 的替代形态『只卖优化建议 + 对账』RM1,200/月现在就能卖,零投放责任」(视角 1)**
  - 为什么不成立:R1–R10 的阈值在 PLAN §2 自己写明「全为占位,A-1 后用实测替换」;R1 刚从 RM60 提到 RM150,原因就是原阈值在 CPL RM50 下会系统性误杀好广告。拿一套一分钱都没验证过的规则按月收客户的钱出「建议」,卖的是没有数据支撑的意见;客户照做亏了钱,责任一样回到他身上,「我没碰你的预算」挡不住。
  - 修正:这个形态也不能卖。至少等自己 A-1 跑完(≥30 进线、无码率 <30%)、用自己的真实数字校准过阈值,届时并进对账包当加价项(+RM300/月),不单独立一个 RM1,200 的档。
- **「包 E 合规闸可以卖,gate_rules 表驱动『客户自己加词即时生效』是可以直接演示的卖点」(视角 1)**
  - 为什么不成立:gate_rules 只是已建的 14 张表里的一张空表,读这张表的 Gate v2 / SE-01 一个都没上线(排在 Phase 1),现在没有任何东西可以演示。正在跑的 v3.9.19 里的 Gate 只有四条(长度 / 关键词 / HALAL / 首句点名产品),不是 SPEC 里那套三语禁词 + 20 种病名 + MAL/KKLIU 逻辑。
  - 修正:现阶段它是「文档产品」不是「系统产品」:能卖的是 Excel 词表 + 人工过闸清单 + 授权信模板 + 一次讲解,价格 RM500–1,200 一次性,而且必须先花 RM800–2,500 问一次大马律师。自动拦截的演示要等 Phase 1 真上线。
- **「包 E 的目标客户是保健品直销团队与上线」(视角 1、视角 3)**
  - 为什么不成立:这群人的真实阻塞不是「哪些词不能写」,是「公司批不批」。KKLIU 批文只签发给持 MAL 的品牌方,分销商申请不了;公司书面许可也只有公司能给。这两样他都卖不了,一张词表解决不了客户真正的痛,客户付钱后会发现自己还是不能发。
  - 修正:词表只能当赠品或加购,不能当主打。真正能卖给这群人的是「帮你把申请信写好、帮你跟进公司回复」这种行政协助,值 RM200–500,不值 RM1,800–3,500。
- **「在他自己所在的 3 个 Telegram 同行群里对团队领袖一对一发软邀约」「首批客户是下线与同公司分销商」(视角 1、视角 2)**
  - 为什么不成立:三份评估都漏了同一条:他此刻正在向公司申请书面发帖许可,而向同公司其他分销商推销自己的付费服务,在多数直销公司合约里属于跨线招揽 / 推销非公司产品,常被明文禁止。被投诉一次,不是丢一个客户,是许可信直接谈崩——而 Phase 1 和整个广告引擎都压在那封信上。用一个月赚 RM300 的生意,去赌一条价值 60 天工期的关键路径,划不来。
  - 修正:在公司书面回复到手、并且在同一封信里问清「我能不能向其他分销商提供付费的技术服务」之前,一个同公司分销商、一个下线都不碰。首批客户只找非保健品、与公司无关的本地商家(修车、补习、美容、装修、宠物、建材)。
- **「90 天内签 2–4 个客户」「第 12 周 MRR RM560–2,300」(视角 2 base、视角 3 base)**
  - 为什么不成立:三份评估自己都写了:第一个客户 onboarding 20–25 小时、同一时间只能做一个、新签上限 1 个/3 周,而净可支配工时只有 17–26 小时/月。光第一个客户就吃掉整整一个月的全部工时——而这一个月里他自己的 Phase 0a/0b 还没跑完、IG 还没养、广告 A-0 还没开。视角 2 的 base 更是建在「2 个付费机器人客户」上,而机器人包它自己说要等通道答案:前提未定就写进了 base。
  - 修正:90 天内现实上限是 1 个客户,而且大概率是案例价。第 90 天 MRR RM0–300,一次性收入 RM0–1,200。把「签 2–4 个」当目标,一定会挤掉自己生意的关键路径。
- **「第 3–4 周花 RM3,000–8,000 做开办:SSM + 律师合同 + 专业责任险」(视角 3)**
  - 为什么不成立:顺序反了。一个客户都没有、第一个产品还没定型就先花掉三到八千,是典型的「准备到死」。专业责任险对一个还没注册、没营收、没客户的一人实体既难买也不该买;律师起草合同也该等产品定型、知道到底要承诺什么之后再做,否则是花钱买一份要重写的东西。
  - 修正:现在只花约 RM60(SSM 独资注册,目的只是能开发票)+ 0 元自写一页服务条款(不保证平台不封号 / 数据归客户 / 提前 14 天可停 / 客户权限逾 14 天未到位项目暂停且已投入工时不退)。律师合同(RM800–1,500)放到签第一个付费客户前一周;责任险先拿报价、不投保,真要替客户托管系统或持有客户凭证时再买。
- **「n8n 授权可能一票否决 B/A/C 三包」(视角 3)**
  - 为什么不成立:方向对,范围写宽了——这条是收窄不是推翻。Sustainable Use License 限制的是「替第三方托管 n8n 当服务卖」和「把 n8n 嵌进商业产品」;如果每个客户在自己名下的服务器、自己的账单上跑自己的 n8n,他只收配置与运维人工费,那属于客户的内部业务用途,通常不需要额外授权。说成三包全否,会让人干脆什么都不做,反而错过唯一安全的形态。
  - 修正:不是三包全否,而是一条铁规:一律不做代托管。客户自持实例、自持账单、自持全部账号所有权,他只卖配置与运维工时。这条同时解决了授权、凭证隔离和「他跑路了客户怎么办」三个问题。邮件仍然该发给 n8n 官方确认,但不必因为等这封邮件停掉所有动作。
- **「进度落后 2–4 天(且有进一步扩大风险)」(进度图 overall_verdict)**
  - 为什么不成立:只量了 Phase 0a 的工时缺口,没量关键路径。Phase 1 的两个前置都有外部时钟、而且都没启动:公司书面许可(模板 09-10 就写好,到 09-12 仍未发出,回复周期未知,两三周属常态)和 4 个 IG 各 2 周的手动养号(一天没开始)。就算信明天发出、两周后批复,IG 也要到 09-27 才能接 API;按更现实的 2–3 周回复,Phase 1 实际开工落在 10 月中下旬。对 09-23 这个基线,差的是 3–5 周,不是 2–4 天。
  - 修正:分开讲:技术支线(CC-A 的 n8n 升级 + R22.10 + R22.11、CC-C 的语料)领先或持平;90 天基线的关键路径落后 3–5 周,单一原因是一封没发的信加没开始的养号,跟 CC-B 写得快不快基本无关。CC-B 那六个自主项另外再叠 3–6 个工作日。
- **「广告引擎 2026-09-21 开始搭,最早 10-12 花第一笔钱」(排期建议)**
  - 为什么不成立:09-21 那天,Phase 0a 的六个自主项最多刚做完、Phase 0b 一项没动,而广告引擎的逐条审批按钮、/adstop 急停、归因合流全都挂在 SE-00 Router、SE-07 和告警去重表上——底座没好就建广告流,等于先装水龙头再挖井。另外第二把 token(要 ads_management)得等企业验证,审核时长未知;而 10-12 花钱这个日期隐含「公司在 09-18 前书面回复」,是全套假设里最乐观的一个。
  - 修正:建流起点改为条件触发而不是日期触发:Phase 0a ①–④ 全过 + SE-06/SE-08 已上线,现实落在 2026-09-29 到 10-05。真实花钱最早 2026-10-26,现实 11-09 到 11-23。纸面部分(9 张表建表语句、Gate-Ad 三语词表、SE-22/23 表结构)由云端现在就做,不占 CC-B。
- **「SE-09 花销回填先跑通,就等于提前验证了 A-0 出场条件之一『能 GET /act_X』」(排期建议)**
  - 为什么不成立:SE-09 用的是只读 token(ads_read / read_insights),它只证明「读得到效果数据」,不证明「建得了广告、写得了预算」。A-0 真正的门槛是企业验证 + 第二把带 ads_management 的 token + 写预算后 GET 回读断言 + 账户级原生规则真的生效。
  - 修正:SE-09 通过只能勾掉「读得到」。「写得了」必须单独验一次(先用 RM40/天写进去、GET 回读确认是 "4000" 这个字符串),A-0 出场清单里这两项分开记。
- **「YouTube Shorts 最早 2026-11-09 可以并入半自动内容包」(排期建议)**
  - 为什么不成立:这个日期建在 Phase 2 从 10-07 起算的基线上,而 Phase 1 现在已经要推到 10 月中下旬,Phase 2 顺延到 11 月底以后。另外 Shorts 每周至少 2–3 条才有算法反馈,而老板的实拍产能按 PLAN §3 是每月 2 小时、而且只做 1 条线——多一个平台就是把这个已经紧张的数字再翻一倍。
  - 修正:90 天内不做。最早 2026-12 下旬到 2027-01,而且只做最轻的形态(复用已有口播脚本 + 老板手发 + 来源码加 #YT_ 前缀),不接 YouTube 的接口、不追订阅和分成。
- **「SME 数字化补助 50% 配对、上限 RM5,000,所以 RM8,000 的单子客户自付约 RM4,000」当作定价锚(视角 1)**
  - 为什么不成立:这类补助通常要求服务商是名单内的认可供应商,一个刚注册的独资企业不在名单上,客户拿不到这笔钱。把它写进报价,等于对客户做了一个失实承诺,签约后才发现补助拿不到,是退款加口碑的双重损失。
  - 修正:报价里一个字都不提补助。真想用,先去查自己能不能成为认可供应商,拿到书面结论再说。
- **「四条里有两条没达到就收手,因为自己多成 1 单就是 RM3,000」(视角 1 的 90 天判定标准)**
  - 为什么不成立:RM2,400–3,040 是客单(销售额)不是利润。同一份评估在别处按直销毛利 20–40% 估,取 30% 的话一单毛利大约 RM720–900。拿销售额去跟服务业务的净收入比,会把自营生意的吸引力放大三倍以上;结论方向对,但用错数字做决策,下次遇到边界情况就会判反。
  - 修正:对照口径统一成毛利:多成 1 单约等于 RM600–1,200 毛利(真实毛利率老板自己知道,须由他给一个数)。即便这样,服务业务 base 档整整一个月的净收入,也只等于自己多成 1–2 单。
- **「Apps Script Sheets 桥可以直接复用给客户,托管 1.5–2.5 小时/月」(视角 1、视角 3)**
  - 为什么不成立:这座桥部署在 Google 账号下,每改动一次都要账号持有人自己进「管理部署 → 新版本」重新部署——实况里刚踩过一次(要加一个 GET ?action=blocklist 就得老板重新部署)。换成非技术客户,每次小改动都要远程教他点一遍,还要等他有空,工时不可控。
  - 修正:月度工时按 2.5–4 小时估,不是 1.5–2.5。合同里写明「需要你自己点的步骤每月最多协助 2 次,超出按次计费 RM120」。
