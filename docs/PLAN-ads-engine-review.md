# PLAN-ads-engine 评审记录(2026-09-11,工作流 wf_d96d2782)

流程:三位设计师(创意 / 投放 / 合规与数据)→ 两位评委 → 合成 → 批评家修订。最终版见 `PLAN-ads-engine.md`。

## 致命(已在 v1.1 修正)

- KKLIU 被当成可选的 10% B 轨:马来西亚要求面向公众的注册保健品广告先经药品广告局(MAB/KKLIU)批准,方案把 90% 的量产投放建在「不提功效即免审批」这个未经法律确认的假设上;而付费广告在 Meta 广告资料库公开可搜、付款卡直指老板本人,一旦被查是刑事条文(Act 290)不是平台处罚。必须改成出场硬闸。
- KKLIU 申请主体搞错:批文按素材逐份签发给 MAL 持证公司(品牌方),分销商无法自行申请。方案的「先申 1 线×1 份社媒素材(官费约 RM100、约 30 天)验流程」由老板去做是做不成的,这条路径不存在,只能向公司要已批素材或要公司书面担责。
- 预算单位没定死就安排自动建广告:Marketing API 的 daily_budget / lifetime_budget / spend_cap 以账户货币最小单位(MYR 即 sen)传字符串,RM250/天 = "25000";方案把单位列在「未核实 #7」,写错一位就是 100 倍超支。而 SE-17b 的账户级兜底写的是「日花 >RM300 通知」——只通知不停,救不了。必须:写入后 GET 回读断言 + 原生规则「账户日花 >RM400 自动 PAUSE」。
- 「两把独立 token 不连坐」是错误的风险缓解,却被当成第 1 号风险的解法。Meta 的政策处罚落在 Page / Business Portfolio / 个人层,不落在 token 层;CTWA 又必须绑定同一个 Page,所以广告违规必然连坐自然流量引擎。token 分离只隔离凭证泄露,不隔离封禁。
- R1 早杀阈值会系统性误杀好广告:CPL RM50 时花 RM60 的期望线索只有 1.2 个,纯运气导致 0 进线的概率约 30%(CPL RM60 时约 37%)。再叠加方案自己承认的 30% 无码率(ad 级 CPQL 被系统性高估约 30%),R1/R2 会持续杀掉本来能赚钱的广告,并逼出无谓的创意消耗。阈值应提到 ≥3×实测 CPL,且无码线索必须先按花费占比分摊再算 CPQL。
- SE-13 的「一键全批」与第 6 节「广告 100% 人审,永不自动放行」直接矛盾。更糟的是 SE-23 台账会记录「已人审」——真出事时这份台账是不利证据而不是辩护材料。必须取消一键全批,逐条点。
- 扩量规则缺接单产能闸:RM250/天每天产出 5–8 个合格线索,全靠老板一个人在 WhatsApp 成交,方案同时又承诺「每周 10–15 分钟」。线索堆着不回,对话→成交率会掉,Ratio 必崩,钱照烧。必须加一条:昨日线索 24h 未回 >3 个即冻结扩量并降一档预算。
- 学习期数学自我否定:方案自己算出每 adset 需 RM214–357/天才够 50 事件/周,却仍安排 RM250/天开 4 线、4–8 个 adset(每组 RM31–62/天)。结论只能是四条线长期 Learning Limited,投放效率打折的钱天天在烧。要么 A-1/A-2 只投 1–2 线把单线堆到 ≥RM80/天,要么四线齐投等预算 ≥RM400/天。

## 重要(已修正或标注)

- 漏斗数字自相矛盾:200 点击 × 点击→进线 25–40% = 50–80 进线,方案却写 10–20;用 CPL RM25–60 反推,点击→进线实际只有 3–6%。下游 QL、成交数跟着错,且 §2 的 0.4–0.8 成交/天推出 5–10:1,比 §8 的 4:1 目标乐观一倍——同一份文件里两套互斥的预期。
- A-1 只花 RM560 却写「≥30 进线」的退出标准,隐含 CPL RM18.7,低于方案自己给的 CPL 下限 RM25。RM560 在 CPL RM50 下只买到约 11 个线索,统计上证明不了任何事。要读经济性至少 RM1,500–2,000;RM560 只够验通路。
- 老板时间被严重低估:周日审 24 概念 + 周一上线 + 每天日报 + 「每线每月 10 张 4:5 + 5 段视频」(四线 = 40 张图 + 20 段片)。仅拍摄就是每月数小时,「每周 10 分钟」「稳态 ≤15 分钟」不成立。诚实数字:A-1/A-2 每周 60–90 分钟,稳态每周约 30 分钟 + 每月 2–3 小时拍素材,且不含回 WhatsApp 的时间。
- 产量与槽位不匹配:每周 24 概念 → 上线 6–8 条,但常驻只有 8 条、R7 又 21 天退休,等于每周换掉全部创意。单变量纪律、冠军基准和学习积累全被冲掉。稳态应降到每周全线 2–3 条新 ad、库存 ≥4。
- Marketing API 权限层级现在就能定性,不该列为「可能推迟整个项目」的未知:同一 Business Portfolio 下的系统用户 + Development Access 通常足以管理自有广告账户,无需先过 App Review;真正门槛是 Business 验证与 Development 配额,升 Standard 需近 15 天内 ≥500 次调用、错误率 <15% 并过审。A-0 该验的是 Business 验证是否完成,而不是「要不要 App Review」。
- spend_cap 是账户累计上限,触顶即全账户停投且要手动重置;RM8,000 在 RM250/天下约 32 天用完。方案只在三个阶段各调一次,没有「用到 80% 告警」和重置 SOP——最可能的结局是某天早上广告全停而没人知道。
- 期望收益被当成承诺写:「8 周 RM5,880 → 期望销售 RM23,500」「稳态 RM7,500 → RM30,000/月」直接套 4:1,没有下行情景。对老板必须并列讲:做不到 1:1 就是白亏 RM5,880。
- 老板摘要把「历史 25.9:1」当卖点讲,但方案第 1 页自己就说这个口径是坏的(含老客回购、Enquiry 与 Closed 不同批)。对外引用坏口径会形成错误预期。
- R8 冠军保护写「任何情况下不自动 PAUSE」缺例外:合规 block、freq ≥4 的烧号、账户级红线都必须能停。
- R9 自动补位与「加法永远慢于减法、一律老板按钮」表面矛盾,需要在文里说明它不改预算、只在已批库存内补位,所以可以自动。
- SE-23 台账留存 3 年偏短。马来西亚商业账簿/税务惯例是 7 年,合规辩护材料按更长的那个留。
- n8n 本身宕机或升级窗口时 /adstop 也用不了,方案缺一个不依赖系统的人工急停:老板手机 Ads Manager 把账户支出上限改成当前已花额,应写进 SOP。
- CTWA 带码的机制没写清就当成 A/B 双轨的前提。已查到:CTWA creative 用 page_welcome_message(内含 autofill_message)设预填首句,ctwa_clid 只出现在 WhatsApp Cloud API 的 referral 回调里(referral 还带 source_id / source_type=ad)。这两点应写进方案正文并标注待实测,而不是停留在未核实清单。

## 老板摘要(v1.1)

- 三件事没落地之前,一分钱广告都不花:公司书面许可、KKLIU 怎么处理、你每天能回几个线索。
- KKLIU 批文只有持 MAL 的公司能申请,你自己申请不了。要么公司给已批素材,要么公司书面认下「不提功效版」的责任——两者都没有就只发自然帖。
- 目标 Sales:Ads ≥4:1。历史那个 25.9:1 含老客回购,不是广告成绩,别拿它定预期。
- 预算不跳级:RM40→80→150→250,先只投 1 条线;四条线一起投要等日预算到 RM400,不然全部卡在学习期白烧。
- 第一笔学费约 RM1,600(不是 RM560),买的是真实获客成本和归因通不通,不是这阶段赚钱。
- 广告逐条你点批准,没有一键全批——广告进 Meta 广告资料库谁都能搜到,责任在你名下。
- 亏钱的广告机器自动关,加钱永远你点;线索 24 小时回不过来,系统自动冻结扩量并降预算。
- 广告出事会连累同一个 Page 的自然流量,这躲不掉,所以前 4 周只投 1 条线试水。
- 你的真实时间:头两个月每周 60–90 分钟,稳态每周约 30 分钟,另加每月 2–3 小时拍素材——回 WhatsApp 的时间还不算在内。
