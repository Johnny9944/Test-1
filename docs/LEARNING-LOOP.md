# wabot 的「学习回路」:资料怎么喂、怎么用、怎么迭代(2026-09-15)

> 老板问:「机器学习现在喂了资料了吗?要怎么分配、分析资料才能让机器更好地运用,甚至自我迭代/进化?」

## 0. 先说清楚:wabot 不是「训练」出来的
- 主线 Brain 是一个托管的大模型,每条入站消息调用一次。我们**不训练它、不微调它**(24 个案例微调毫无意义,还会把公司规矩训坏)。
- 所谓「喂资料」= 在它回复的那一刻把对的东西放进上下文:公司规矩、禁词、这条线的策略卡、这个客户的历史。这叫检索/上下文工程,不叫训练。
- 所以「学习」发生在系统外面:数据 → 分析 → 规则/策略卡 → 写进配置 → 上线 → 量结果 → 再改。机器「进化」的速度 = 这个回路转一圈的速度 × 数据量。

## 1. 现在喂到哪一步
| 资料 | 状态 | 有没有进主线 |
|---|---|---|

| 24 个真实会话 → 案例分析 → 8 张策略卡(6 张低置信) | 已出;干跑入库中 | 未接 Brain(R22.13) |

诚实结论:资料喂了一半,回路还没闭合。机器人今天跑的还是原来的提示词。

## 2. 闭合回路(每周转一圈)
| 步 | 做什么 | 谁 | 门槛 |
|---|---|---|---|
| ① 记 | 每个会话自动打标:来源码、首句意图、阶段、异议、成交/流失、流失点;老板成交回一条「成交 后4位 金额 产品」 | CC-A(R22.12 + 成交协议) | 手机号打码,数据属公司 |
| ② 析 | 每周把新会话跑 case-analyze,刷新策略卡;n_cases <10 的卡标低置信 | CC-C | 每周一 |
| ③ 用 | Brain 按线 × 画像取卡:开场、异议回应、成交触发;疗效/折扣词只做禁词 | CC-A(R22.13) | Core Logic 变更走 harness 三个数 + 哈希证明 |
| ④ 试 | 新卡先做**离线回放**:把新提示词放回过去的会话上重跑,用评分表(合规 / 回应对题 / 推进阶段)打分,不比旧版差才上线;上线后 A/B 各半 2 周 | CC-A + 主控 | n ≥30 才算数 |
| ⑤ 量 | 每周看:成交率、A Client 转化、平均成交时长、流失点分布;抽 5 条人工核 | 主控晨报 | 准确率 <90% 停自动写回 |
| ⑥ 改 | 只改赢的:某张卡成交率显著高就扩大;差的回退 | 主控核对后按 §9 上线 | 每周最多改一次 |

「自我迭代」= ②③④ 自动跑,⑥ 由主控核对后放行。**不做**「模型自己改自己提示词然后直接上线」:多 agent 实验里无人核对的自改会放大错误,而且指标是成交率这种可被投机的代理指标(例如学会了催单),必须有人看一眼。

## 3. 数据够不够
- 24 个会话太少。策略卡要可信,每条线至少 100–300 个带结果标签的会话;按每天 1–3 条进线,是几个月的量。
- 所以最快让机器变聪明的不是更花哨的算法,是**更多流量 + 每一条都打上标签**。11 月开投之后数据才会开始积累。
- 真正能上「机器学习」的一块:A Client 意图判定。等有 500 条人工标过的消息,可以训练一个小分类器替换关键词规则;在那之前用词典。

## 4. 现在就做的三件(不等流量)
1. R22.13 方案:Brain 读策略卡 + A/B 开关 + 无卡走原逻辑(CC-A 写方案,主控核对)。
2. 离线回放评测:用现有 24 个会话 + harness 的 90 个用例,给「新提示词 vs 旧提示词」打分的脚本(CC-A)。
3. 每周分析排程:CC-C 周一刷新策略卡与市场扫描,主控周二晨报汇总。

数据归属提醒:客户资料属公司,分析产物只用于卖公司产品;脱敏后的聚合(策略卡)可以进本地 git,原始会话不进。
