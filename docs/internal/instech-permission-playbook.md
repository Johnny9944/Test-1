# 内部文件:Instech 授权申请怎么走(不对外发送、不截图、不转发)

对外版只有 docs/letters/instech-permission-outgoing.md 的 A/B/C 三段。本文件是内部打法。

## 顺序
1. 只发 A(WhatsApp 给 Yssi 姐)。不要先递正式信;等她说「你写一份给我」再用 B 或 C(二选一,分行层级中文即可,总公司用马来文),收件人由她指定。
2. 三天没回再轻轻补一句「Yssi 姐不好意思打扰,上次问的那个你看到了吗,不急」。不要连续追。
3. 先做一张「合规版样帖」(产品图 + 一段不涉功效的文案)给她看实物,比看条款容易点头。
4. 发信前先自查现有 FB 帖子:有涉及功效的先下架或改写,否则公司一批准、顺手去看账号,授权会变成纪律处分。
5. 公司或领导的任何回复原文保存一份(social-engine/compliance/),作为后续内容制作的依据。

## 为什么删掉了两个问题
- 「完全不提功效的版本认不认、责任怎么分」:书面自证「我知道有风险在找规避办法」,公司标准答案只会是「不批准」;而且 Act 290 与 Medicine Advertisements Board Regulations 1976 管的是任何指向健康用途的表述(见证、before/after、「睡得好了」都算),「不提功效」不是安全港。这个问题只能由公司自己的守则回答,不要用文字问任何人。
- 「向其他分销商卖技术服务」:与第 1–5 条捆在一起会让整封信被读成「借公司的产品和网络做自己的软件生意」,连带把容易批的事一起否掉;书面问等于逼公司白纸黑字说「不可以」,以后连私下做都不行。正确路线:先拿许可 → 自己老实用 3–6 个月做出数据 → 等团队里有人主动来问 → 当面/通话对 Yssi 说「有人来问我能不能帮他弄一样的,我不敢乱答应,想问你我该怎么处理」。永远被动、永远口头、永远把决定权交给她;她愿意去问公司,提案人就是她,通过率天差地别。

## KKLIU 用词
KKLIU 是批准编号前缀(如 KKLIU 1234/2025),不是一套「要求」;审批机构是卫生部 Medicine Advertisements Board / Lembaga Iklan Ubat(LIU)。四个产品若是 MAL 注册产品,广告须 LIU 批准;若只是一般食品,归 Food Act 1983 / Food Regulations 1985,不需要 KKLIU。信里让公司确认类别,不替公司下结论。

## 系统侧的门槛(不变)
- 拿到第 1、3 条书面(或分行主管 WhatsApp/电邮)确认前:IG/Threads 自动发帖不开,FB 现有节奏不变。
- 第 4 条答案决定广告引擎能否启动;没有 LIU 批文或公司统一申请的路径,就只做自然帖。
